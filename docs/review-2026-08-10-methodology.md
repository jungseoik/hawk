## 1. 최우선 — 상보성 항등식이 학습 입력에서 성립하지 않음

논문 최상위 기여 C1(수식 2, `M ⊙ x + (1 − M) ⊙ x = x`)이 **모델이 실제로 보는 텐서에서
깨진다.** 세 스트림이 서로 다른 위치로 크롭되기 때문이다. 원본 HAWK 로더에서 물려받은 동작이며
CERBERUS가 도입한 결함은 아니지만, 논문 주장은 그와 무관하게 무너진다.

파급 범위:
- §3.1.3 `L_sim` 정당화("동적 스트림은 외형 프레임의 공간적 부분집합에서 파생되므로")
- §4.2 수식 (11) Coverage 해석("합집합이 외형 스트림의 전체 프레임 정보를 보존")
- §4.5 BSI 합성 연산자의 정합성

**조치 선택지**
- **A. 로더 수정 후 Stage-2 재시작** — 크롭 파라미터를 1회 샘플링해 세 스트림에 공유
  (`get_params`를 외부에서 호출하고 `F.resized_crop`을 동일 인자로 3회 적용).
  Stage-1이 어긋난 채 학습된 불일치는 §4.1에 명시.
- **B. 로더 수정 + Stage-1부터 재학습** — 완전 정합, 추가 약 35시간.
- **C. 수정하지 않고 C1을 "증강 이후에는 근사적으로만 유지"로 약화** — 비용 0, 기여 약화.

## 2. 두 좌석이 독립적으로 합치한 지적 (교차 검증됨)

1. **seed·분산·유의성 전무.** 참조 어블레이션 델타가 BLEU-1 기준 0.01–0.02 대역인데 전 표가
   단일 점추정. 최소 3 seed + 부트스트랩 CI, 또는 단일 seed임을 한계로 선언.
2. **`+ Static Stream` 행이 세 가지를 동시에 변경** — 파라미터, 시각 토큰 ×2→×3, 입력 구조.
   이 행 하나로는 "토큰이 많으면 좋다"만 증명된다.
3. **`+ L_BL` 행은 Stage-2에서 구현 불가.** `L_BL`은 Stage-2에서 통합 목표로 흡수되므로
   (§3.6, `video_llama.py:806`) 별도의 Stage-1 재사전학습을 요구한다. §4.8 표에 각 행이 어느
   stage에서 분기하는지 명세가 없다. `experiments/configs/ablation.yaml`의 6행 행렬도 §4.8의
   4행 누적 구조와 불일치하며, `scripts/run_stage2.sh`의 절제 스위치는 미구현 상태.
4. **용량 통제의 오배치.** §4.7(일반성)이 아니라 §4.8 주 어블레이션의 필수 행이어야 한다.

## 3. 어블레이션 설계 — 현행으로는 인과 주장이 성립하지 않음

누적(cumulative) 구조라 순서 의존적이고 leave-one-out이 없어 상호작용항을 식별할 수 없다.
`L_dis`가 마지막에 놓여 "L_dis 없는 정적 스트림"이 오히려 유해할 가능성(중복 붕괴)이 은폐된다.

**추가해야 할 행**

| 범주 | 행 | 목적 |
|---|---|---|
| 음성 통제 | 무작위 셔플 마스크 | 효과가 사라져야 "구조" 주장 성립 |
| 음성 통제 | **다른 비디오의 배경** | 여기서 이득이 남으면 "그 비디오의 맥락"이 아님 |
| 음성 통제 | 시간축 뒤섞은 배경 | 시간 정합성의 기여 분리 |
| 용량 통제 | 외형 스트림 복제 / 단일 스트림 토큰 ×3 | 구조 vs 용량 (§4.7에서 이동) |
| C1 대조군 | 정적 입력을 옵티컬 플로우 이미지로 대체 | **C1의 유일한 직접 증거** |
| C1 대조군 | 정적 입력을 RGB 차분으로 대체 | 동상 |
| leave-one-out | Full − Static / − L_BL / − L_dis | 상호작용 식별 |

음성 통제 3행은 **동일 파라미터·동일 토큰 수**에서 수행해야 의미가 있다. 각 행에
파라미터 수·토큰 수·분기 stage 열을 함께 표기할 것.

## 4. 실험 세팅에서 확정해야 할 것

- **마스크 비율 통계** (심사자 실측, 데이터셋당 6클립 × 8프레임, τ=0.2 동일 설정):

  | 데이터셋 | motion-mask 비율 (mean/median) | 정적 스트림 잔여 |
  |---|---|---|
  | DoTA (대시캠) | **0.516 / 0.541** | 48% |
  | CUHK Avenue | 0.204 / 0.147 | 80% |
  | Ped1 / Ped2 | 0.282 / 0.226 | 72–77% |
  | UCF-Crime | 0.079 / 0.046 | 92% |
  | ShanghaiTech | 0.063 / 0.060 | 94% |
  | UBnormal | 0.053 / 0.025 | 95% |

  **H1과 정면 충돌한다.** H1은 교통 도메인에서 최대 이득을 예측하는데, 바로 그 DoTA에서
  ego-motion이 화면 절반을 동적으로 분류한다 — §1.1의 동기 예시 "눈 덮인 노면"이 대시캠에서는
  동적 스트림으로 귀속된다. 반대로 정지 카메라 데이터셋에서는 정적 스트림이 원본의 92–95%라
  사실상 외형 복제본이고, 동적 스트림은 5% 남짓의 거의 빈 입력이다. 그 상태에서 `L_dis`와
  `L_sim`이 동일한 `z_m`에 상충 방향으로 걸린다.
  → 전수 재측정 후 §4에 필수 표로 보고. ego-motion 보상(전역 호모그래피 후 잔차 플로우) 조건
  추가 여부를 조기에 결정. H6(단일 τ ≈ 0.2 균형점)도 10배 차이 앞에서 재기술 필요.
- **seed 결정론 복구** — 샘플별 재시드 제거, worker seed를 `base_seed + worker_id + epoch`로.
- **디코딩 설정 고정** — greedy. temperature > 0이면 BSI에 양의 편향이 들어가 H3를 인공적으로
  만들 수 있다. sampling을 쓸 경우 동일 입력 반복의 자기 일치도를 baseline으로 감산.
- **평가 하네스 부재** — 레포에 BLEU/GPT-guided 계산 코드가 없고 `run_eval.sh`는 Gradio 데모다.
  §4.10의 재현성 주장을 현재 제공 범위로 좁히거나 하네스를 실제로 추가할 것.
- **BSI null 조건** — 의미상 동등한 배경(safe → safe′)으로 교체 시 BSI ≈ 0 확인. 없으면 높은 BSI가
  "맥락의 인과적 활용"인지 "픽셀 섭동 민감도"인지 구별되지 않으며, `ΔBSI`도 이를 상쇄하지 못한다
  (정적 스트림 보유 모델이 합성 아티팩트에 더 민감하다는 대안 가설이 남는다).
- **선형 프로빙 명세** — 레이블 `y`, 분할, 분류기 용량·정규화, chance level이 전부 미정의.
- **CDS 기준축** — `Coverage`의 기준 `z_a`가 `L_sim`으로 학습되는 표현이라 설정마다 자[尺]가 함께
  움직인다. 동결 인코더 특징 등 학습에서 자유로운 기준으로 고정하고, `[z_m ; z_b]` 연결 시
  블록별 정규화를 적용할 것. `L_dis`가 걸리지 않는 층위(decoder_2 출력)에서의 CDS가 C5의 진짜 증거.
- **E1 추출 경로 불일치** — `scripts/extract_representations.py:66-72`가 transform 없이
  원본 해상도·`[0,255]` 스케일로 인코더에 넣는다(학습 입력은 224×224·`[0,1]`). E1 수치 전체가
  off-distribution에서 측정된다.

## 7. 인정된 강점 (두 좌석 공통)

- 결과 이전에 배치된 confound 통제가 실재한다 — ΔBSI 증분 설계, CDS의 이중 방어(선형 프로빙 +
  동일 입력 상한 통제군), §4.7 용량 대응 baseline. 통상 rebuttal에서야 나오는 방어를 선점했다.
- 가설 H1–H6의 사전 확정으로 HARKing 위험이 구조적으로 낮다.
- §3.1.4가 occlusion·준정지 객체 귀속을 한계 절이 아닌 정의 직후에 선언한다. "무손실"의 의미를
  스스로 좁힌 절제도 정확하다.
- **Stage-2 손실 구조를 정확히 기술했다** (§3.6: `loss_motion = loss_background = loss`).
  이 계보 후속 논문이 가장 흔히 범하는 사실 오류를 피했고 구현과 일치한다.
- E3(손실 방향 인과 검증)는 원고에서 **한 행이 윗 행과 정확히 하나만 다른 유일한 비교**이며,
  `experiments/loss_direction.py`로 메커니즘이 이미 시연되어 있다.
