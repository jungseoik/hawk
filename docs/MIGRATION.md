# Server Migration & Resume Guide (CERBERUS)

How to move this project to another server and **resume Stage-1 training from where it
stopped** (currently `checkpoint_53`, paused at epoch 54). Nothing needed for this is lost:
everything is either in git, on Hugging Face, or re-downloadable by script.

## What lives where (inventory)

| Asset | Location | How it moves to the new server |
|---|---|---|
| Code, configs, scripts, docs, paper (+ HAWK PDF), `.claude/` (skills/agents/memory) | **Git** (`jungseoik/hawk`, branch `main`) | `git clone` |
| Checkpoints `checkpoint_0..50` (5-step) **+ `checkpoint_53` (final stop)**, `config.yaml`, `run_info.txt`, `train.log`, `loss_curve.png`, `STOPPED.md` | **HF** `backseollgi/Cerberus/stage1_core/` | `scripts/download_checkpoint.py` / `hf download` |
| LLaMA-2-7B weights (~13 GB) | not transferred | re-download (`hf download`, step 3) |
| WebVid dataset (~1.1 TB extracted) | not transferred | re-download + extract by script (step 4) |
| **HF token** (`/data/pia/.hf_token`) | **secret — NOT in git** | manually re-create on new server (step 0) |
| `data/` (~1.8 GB: smoke/bench/diag **test logs & sample clips**) | gitignored | **throwaway — do not migrate**, regenerated by tests |
| `weights/`, `output/`, `hawk/runs/`, `*.pth`, `*.log` | gitignored | regenerated / from HF |

> Nothing important is untracked-and-unmanaged. Repo `data/` is only disposable test output.

## New-server bootstrap (clone → resume)

```bash
# 0. HF auth (token is a secret, never committed). Put your write token here:
mkdir -p /data/<you> && umask 077 && printf '%s\n' 'hf_xxx...' > /data/<you>/.hf_token
export HF_TOKEN=$(cat /data/<you>/.hf_token)

# 1. Code
git clone https://github.com/jungseoik/hawk.git && cd hawk

# 2. Environment (self-contained: torch cu128, full stack, pyarrow, hf_transfer, spaCy, pip -e .)
bash scripts/setup_env.sh --full && conda activate cerberus

# 3. LLaMA-2-7B base weights (~13 GB)
HF_HUB_ENABLE_HF_TRANSFER=1 hf download DAMO-NLP-SG/Video-LLaMA-2-7B-Finetuned \
  --include "llama-2-7b-chat-hf/*" --local-dir weights/Video-LLaMA-2-7B-Finetuned

# 4. WebVid dataset (download parquet -> extract mp4). See docs/reproduce.md / data_webvid_setup.md.
nohup python scripts/resilient_hf_download.py \
  --repos jxie/webvid_10m jxie/webvid_10m_part_0 jxie/webvid_10m_part_1 \
  --base /data/<you> --include "data/*.parquet" > /data/<you>/dl.log 2>&1 &
python scripts/build_webvid_split.py --single /data/<you>/webvid_extracted

# 5. Pull the checkpoint to resume from (newest = checkpoint_53) + its metadata
python scripts/download_checkpoint.py --run-dir /data/<you>/runs/core --latest --meta
#   -> lands at /data/<you>/runs/core/main/checkpoint_53.pth

# 6. Fix the machine-specific paths in the config (see next section), then resume:
bash scripts/train_run.sh configs/train_configs/stage1_main.yaml core 0,1 2
#   train_run.sh auto-resumes from the newest checkpoint in the run dir (epoch 54 onward),
#   restoring model + optimizer + AMP scaler + LR schedule + epoch.
```

## Paths to adjust for the new server
`stage1_main.yaml` (and `eval.yaml`) hold absolute paths from this box — edit to the new host:

| key (file) | this box | change to |
|---|---|---|
| `model.llama_model` (stage1_main.yaml:7, eval.yaml:16) | `/home/pia/seoik/hawk/weights/...` | new repo's `weights/...` path |
| `datasets.webvid.build_info.anno_dir` | `/data/pia/webvid_extracted/annotations/` | new data path |
| `datasets.webvid.build_info.videos_dir` | `/data/pia/webvid_extracted/videos/` | new data path |
| `run.output_dir` | `/data/pia/runs/...` | overridden per-run by `train_run.sh`; set `RUNS_ROOT` env |
| token file path (upload/download scripts) | `/data/pia/.hf_token` | `$HF_TOKEN` env or `~/.hf_token` (scripts check both) |

Also set `RUNS_ROOT=/data/<you>/runs` when calling `train_run.sh` if not using `/data/pia`.

## Verify resume worked
Log shows `Resume checkpoint from .../checkpoint_53.pth` then `Start training epoch 54`.
LR/optimizer continue from the stop point; TensorBoard curve continues (global step = epoch*iters+i).
